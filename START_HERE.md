## Fixed minimal product

- One operator-owned immutable manifest, finite controller-managed cohort and owned synthetic GitHub repository.
- Two distinguishable monitored workloads using the same **actually evaluated** native credential. An extra Native investigator has only context-read/incident-create authority.
- A single local Node/TypeScript backend, browser case page and transactional SQLite control journal. ClickHouse is an analytical projection, not the authority for human approval.
- Raw native snapshots, all-version conflict checks, event-specific acting-subject binding, explicit gaps and a sealed/published/readback-checked generation.
- Exact all-candidate ClickHouse evaluation at bounded historical event-time anchors and current cutoff. Window `(T−600s,T]`; full timestamp ties; pinned effective start; current count and historical witness separate.
- Grounded actual hosted context read and incident, human review of the exact stored scope, native UI/verified CLI policy application, fresh target refusal and inspected control result.
- One readable timeline; actual controlled case and separately labeled replay measurement; sanitized evidence and submission.

The 20/60 allowances and 30/40 counts are illustrative fixture parameters. Establish the event unit and declare the allowance before the actual scenario. Do not promise one tool call equals one permission decision. “Within observed envelope” is provisional for the captured cohort, not proof of source finality, task correctness or global safety.

## Start now or anytime; set up in this order

1. Record team names/emails, actual event instructions, account access and owner responsibilities. Confirm prize stacking/entry routes with staff without making that a technical dependency.
2. Prove actual hosted GitHub calls and the native acting-subject/credential/operation/unit/clock evidence for each workload. Inspect mode, grants, default fallback and endpoint permissions. Preserve response shapes before writing the normalizer.
3. Establish finite source capture and task graph. Missing per-event mapping, credentials or pages remain unknown. Verify the actual native ID identity domain.
4. Create the minimum event source and control journal/collector from those observed contracts. Use the schema/query proposal as a proposal; execute real INSERT/SELECT and generation/binding/context readback before admitting a case.
5. Apply a known trial narrow DENY through actual native UI/verified CLI; retain its selectors and fresh target/control receipts. Restore only the known trial rule, prove the allowed baseline and pin the main manifest before running the controlled incident.
6. Complete the entire actual query-selected case → real investigator read/issue → reviewed native action → fresh target/control result loop. Prioritize this core over optional features; there is no time-based cutoff.
7. Measure a labeled replay only after correctness. Record the actual demo, preserve sanitized proof, grant reviewers access and submit when the required deliverables and access are ready.

The [first-hour checklist](docs/build/FIRST_HOUR.md) contains required receipts and dependency-specific failure paths. The architecture does not promise a public policy-mutation REST API; do not build a fake automatic containment adapter.

## Cuts and honest fallback

Do not add a second vulnerability app, 28-generation portfolio, broad SOC platform, new MCP/OAuth bridge, custom receipt server, automatic recovery or new sponsor infrastructure to rescue a failed main proof. Optional native outcome matching follows the complete core loop; the planted-ticket comparison follows essential fixture/native setup; focused Semgrep discovery stays in the same codebase. Use narrow objectives and diagnostic checkpoints. Each can be omitted with an explicit scope/evidence reason, without a clock-based cutoff.

If selective native enforcement cannot be proved, the surviving monitoring/investigation result is weaker and must be labeled accordingly. CrossedLine only becomes a rescue if a genuine same-workflow finding, owned reproduction and alternate control already work. Shared account/setup failures can affect both plans.
